DPP 后端部署教程

DPP 同步后端 = Cloudflare Worker + D1。浏览器端先把数据端到端加密，Worker 只保存密文或密文分片，不持有解密密钥。代码位于 packages/sync-worker。

架构

浏览器扩展 -> POST /api/sync/push （密文批量上推） -> GET /api/sync/pull （按游标增量拉取） -> GET /api/sync/pending （待确认计数） -> Cloudflare Worker -> Durable Object 串行化 push（只避免并发写竞争，不存业务数据） -> D1 operations 追加日志（cursor / 唯一约束 / fingerprint 冲突检测）
  • D1 负责游标、唯一约束、fingerprint 冲突检测、分页拉取和 pending 统计。
  • Durable Object 不保存业务数据，只把并发 push 在「查询后写入」之间串行化，防止竞争。
  • Worker 全程只见密文，无法读取任何业务内容。

0前置条件

  • Node.js 20+、pnpm 10+
  • Cloudflare 账号
  • 由 Cloudflare 托管的域名（仅自定义域名需要）
  • Wrangler OAuth 登录权限：Workers、D1、Durable Objects、Routes、Secrets
# 所有命令从仓库根目录执行
pnpm install
pnpm --filter dpp-worker exec wrangler login
pnpm --filter dpp-worker exec wrangler whoami
安全红线：不要把访问令牌、Service Account JSON 或其他 Secret 写入 Git、配置文件或命令历史。

1创建 D1

wrangler.toml 中的 database_id 是占位符，部署前必须创建自己的 D1 并回填 UUID：

pnpm --filter dpp-worker exec wrangler d1 create dpp-sync
pnpm --filter dpp-worker exec wrangler d1 create dpp-sync-test

将返回的 database_id 分别写入 packages/sync-worker/wrangler.toml 的顶层与 env.test 两处——D1 binding 不会从顶层继承到命名环境，两个位置都必须配置。

2配置域名

默认使用 Wrangler 输出的 workers.dev 地址；如需自定义域名，取消注释并按你的 zone 修改：

[[routes]]
pattern = "sync.example.com"
zone_name = "example.com"
custom_domain = true

[[env.test.routes]]
pattern = "sync-test.example.com"
zone_name = "example.com"
custom_domain = true

3应用 D1 migration

先测试，后生产：

pnpm --filter dpp-worker exec wrangler d1 migrations apply dpp-sync-test --remote --env test
pnpm --filter dpp-worker exec wrangler d1 migrations apply dpp-sync --remote

检查结果：

pnpm --filter dpp-worker exec wrangler d1 info dpp-sync-test
pnpm --filter dpp-worker exec wrangler d1 info dpp-sync

4配置访问令牌

生产和测试使用不同的高熵令牌（交互式输入，不进命令历史）：

pnpm --filter dpp-worker exec wrangler secret put SYNC_ACCESS_TOKEN --env test
pnpm --filter dpp-worker exec wrangler secret put SYNC_ACCESS_TOKEN

统计看板使用独立的管理令牌 STATS_ADMIN_TOKEN，与同步令牌互不相同——团队成员持有同步令牌也无法查看统计，仅管理员知晓：

pnpm --filter dpp-worker exec wrangler secret put STATS_ADMIN_TOKEN --env test
pnpm --filter dpp-worker exec wrangler secret put STATS_ADMIN_TOKEN

管理员查看统计：浏览器打开内部路径 https://<worker 域名>/internal/usage-insights-7c4a9f，页面内输入 STATS_ADMIN_TOKEN。

6部署

始终先发布测试环境：

pnpm release:worker:test
pnpm release:worker

wrangler deploy 是原子替换：命令成功前旧 Worker 继续服务，失败则整体不生效。

打包扩展并发布生产 Worker 一步到位：

pnpm release

7本地开发

# 初始化本地 D1（数据保存在包目录 .wrangler/ 下，已被 Git 忽略）
pnpm --filter dpp-worker exec wrangler d1 migrations apply DB --local

# 启动 Worker
pnpm --filter dpp-worker exec wrangler dev --local --var SYNC_ACCESS_TOKEN:local-token

健康检查（不暴露内部状态，不要求同步 Token）：

curl -i http://localhost:8787/health
curl -H 'X-Access-Token: local-token' http://localhost:8787/health
# 两个请求均返回 { "status": "ok" }

本地接口验证：

curl -X POST http://localhost:8787/api/sync/push \
  -H 'X-Access-Token: local-token' -H 'X-Client-ID: local-client' \
  -H 'Content-Type: application/json' \
  -d '{"ops":[{"id":"local-op-1","clientId":"local-client","table":"encrypted","type":"create","key":"local-op-1","payload":{"iv":"iv","ciphertext":"ciphertext"},"timestamp":1,"keyHash":"key-hash"}]}'

curl -H 'X-Access-Token: local-token' \
  'http://localhost:8787/api/sync/pull?cursor=0&limit=100'

curl -H 'X-Access-Token: local-token' \
  'http://localhost:8787/api/sync/pending?cursor=0&clientId=local-client'

8远程验收

先把目标环境令牌放入当前 shell，避免写进命令历史：

read -s SYNC_ACCESS_TOKEN
export SYNC_ACCESS_TOKEN
export SYNC_WORKER_URL='https://sync-test.example.com'
# 健康检查
curl -i "$SYNC_WORKER_URL/health"

# 推送 → 拉取 → pending 闭环
curl -X POST "$SYNC_WORKER_URL/api/sync/push" \
  -H "X-Access-Token: $SYNC_ACCESS_TOKEN" \
  -H 'X-Client-ID: smoke-client' \
  -H 'Content-Type: application/json' \
  -d '{"ops":[{"id":"smoke-1","clientId":"smoke-client","table":"encrypted","type":"create","key":"smoke-1","payload":{"iv":"iv","ciphertext":"ciphertext"},"timestamp":1,"keyHash":"key-hash"}]}'

curl -H "X-Access-Token: $SYNC_ACCESS_TOKEN" "$SYNC_WORKER_URL/api/sync/pull?cursor=0&limit=100"
curl -H "X-Access-Token: $SYNC_ACCESS_TOKEN" "$SYNC_WORKER_URL/api/sync/pending?cursor=0&clientId=smoke-client"

9发布前检查与运维

发布前的完整自检：

pnpm test
pnpm --filter dpp-worker exec tsc --noEmit
pnpm compile
pnpm lint
pnpm build
pnpm --filter dpp-worker exec wrangler deploy --dry-run --env test
pnpm --filter dpp-worker exec wrangler deploy --dry-run --env ""

运行期查看日志与 D1 状态：

pnpm --filter dpp-worker exec wrangler tail --env test
pnpm --filter dpp-worker exec wrangler d1 info dpp-sync-test

# 检查日志行数与 cursor 范围
pnpm --filter dpp-worker exec wrangler d1 execute dpp-sync-test --remote --env test \
  --command 'SELECT COUNT(*) AS count, MIN(server_seq) AS min_cursor, MAX(server_seq) AS max_cursor FROM operations'

导出 D1 备份：

pnpm --filter dpp-worker exec wrangler d1 export dpp-sync-test --remote --output dpp-sync-test.sql
备份文件可能包含密文、身份标识和同步元数据，不要提交到 Git。

10回滚

pnpm --filter dpp-worker exec wrangler versions list --env test
pnpm --filter dpp-worker exec wrangler rollback --env test

Worker 回滚不会回滚 D1 schema 或数据。涉及 schema 的发布必须先备份，并提供向前兼容的 migration；不要修改或删除已应用的 migration 文件。

11故障排查

现象检查
401 Unauthorized目标环境是否设置正确的 SYNC_ACCESS_TOKEN，扩展是否使用同一令牌
DB is undefinedd1_databases 是否同时配置在顶层和 env.test
no such table: operations是否对对应环境应用了 D1 migration
push 返回 409相同客户端操作 ID 已存在不同 fingerprint，检查客户端身份和重试数据
自定义域名不可达域名是否由当前 Cloudflare zone 托管，routes 是否匹配
部署到了错误环境显式使用 --env test 或 --env ""
不要通过清空 D1、重置客户端 cursor 或删除本地 IndexedDB 来规避同步问题——这些操作可能造成重复应用或数据丢失。
