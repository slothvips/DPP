一分钟看懂 DPP

DPP 是一个跑在浏览器里的侧边工作台。它把测试与开发日常用到的工具——黑板、链接收藏、验证码、Jenkins 构建、页面录制、AI 助手——装进同一个侧边栏，并且让它们共享同一份本地数据库和同一套端到端加密同步机制。

  • 本地优先：所有数据先写入浏览器内的 IndexedDB 数据库（通过 Dexie 管理），没有网络也能完整使用。
  • 端到端加密同步：需要跨设备时，数据在你的浏览器内用 AES-GCM 加密成密文，再同步到你自己部署的同步服务器。服务器只存密文，看不到任何内容。
  • 模块互联：黑板沉淀信息、录制采集现场、Jenkins 验证构建、禅道承载协作、链接负责导航、AI 负责理解与执行——模块之间通过统一的数据层和后台消息中枢互相引用、互相触发。
  • 隐私边界清晰：团队共享数据和个人私密数据用两把独立的密钥加密；本地-only 的数据（如行为统计）永远不会离开你的浏览器。

各运行环境分别负责什么

侧边栏 Sidepanel

扩展的主界面（点击工具栏图标打开）。所有功能模块的 UI 都住在这里；设置页、录像播放器、黑板页、审计页、更新日志页等是另外几个扩展页面。

Background Service Worker

浏览器常驻后台。统一的消息路由器：Jenkins 请求代理、录制消息、同步指令、AI 页面任务、地址栏搜索、定时闹钟（重试/统计）都在这里处理。

内容脚本

注入到你访问的网页里：录制内容脚本负责采集现场，并向页面注入控制台、网络拦截器；禅道、Jenkins 页面增强脚本在页面上注入按钮（上传录像 / 保存令牌）。

同步服务器

由你自己部署的 Cloudflare Worker + D1 数据库。Worker 只校验访问令牌并把密文追加进操作日志，无法读取内容。

Dexie 本地数据库

所有模块共享的 IndexedDB 数据库。表结构、版本迁移都在这里定义；业务代码必须经由统一的 db 助手读写，同步钩子才能感知到每次变更。

SyncEngine 同步引擎

订阅数据库生命周期钩子，把每次变更记录成「操作」，加密、排队、批量推送、拉取合并、垃圾回收，全部在这里完成。

一条数据的完整旅程

以「在黑板里新增一条内容，并在另一台电脑的 DPP 里看到它」为例：

  1. 1你在边栏操作

    在黑板模块输入内容，失焦自动保存。每个模块（黑板/链接/Jenkins/验证器…）都有同样的入口。

  2. 2统一入口写入本地数据库Dexie / IndexedDB

    所有业务读写必须经过 src/lib/db/ 下的助手函数。这一步先落本地，界面立刻可见，断网也能用。

  3. 3SyncEngine 的钩子捕获到变更

    数据库生命周期钩子（creating/updating/deleting）自动把这次变更登记成一条「同步操作」：哪张表、哪种类型、主键是什么、内容是什么，写入待同步队列。

  4. 4在浏览器内完成 AES-GCM 端到端加密密钥不离机

    推送前，敏感字段（表名、操作类型、主键、内容）在本地被加密成密文，并附上一个 keyHash（密钥指纹）。团队数据用团队同步密钥，个人数据用个人私钥——互不可解。

  5. 5超长内容自动分片

    单个密文超过约 2000 字符时，会被切成多个 __sync_chunk__ 分片操作，控制单次请求体积；某一片失败只需重传那一片。

  6. 6批量推送到你的同步服务器Cloudflare Worker

    同步引擎持有互斥锁，每批最多 50 条、请求体不超过 64KB；失败按指数退避自动重试（最多 5 次）。Worker 校验访问令牌后，把密文追加进 D1 的 append-only 操作日志。

  7. 7另一台设备按游标增量拉取

    每台设备记住自己的拉取位置（cursor），只下载这之后的操作；冲突一律按「本地时间戳，后到者赢（LWW）」合并，绝不使用服务器时间。

  8. 8解密、校验、写回本地

    用对应密钥解密；keyHash 不匹配的操作直接跳过——所以拿着团队密钥的设备永远看不到别人的个人数据。同步写入会带上 tx.source === 'sync' 标记，防止再次触发推送形成循环。

同步机制详解

同步是 DPP 里最核心也最容易被误解的部分。它不复制「数据快照」，而是复制「操作日志」——理解了这一点，剩下的规则都是推论。

4.1 操作日志模型：同步的是「变化」，不是「结果」

每一次数据库变更都会被登记成一条结构化的同步操作，大致包含：

  • 推送（Push）：引擎加锁后从待同步队列取批（每批 ≤50 条，请求体 ≤64KB），逐条加密后 POST 到 /api/sync/push。单批失败按 1s 起步的指数退避重试，最多 5 次；仍有失败的会由后台闹钟（Alarm）稍后补推。
  • 拉取（Pull）：GET /api/sync/pull?cursor=…，游标之前的历史不再重复下载，单次上限 1000 条、最多循环 100 页。拉到的操作按 LWW 规则应用回本地表。
  • 永不硬删：删除也是一条 delete 操作；本地执行的是「软删除」（记录打上 deletedAt 时间戳）。这样其他设备能收到「这条没了」的消息，数据也保留了恢复的可能。
  • 垃圾回收：本地已推送成功的操作记录保留 30 天后自动清理（回拉靠稳定的 clientId 过滤、远端操作靠幂等日志保证安全），防止 operations 表无限增长。

4.2 加密与密钥体系：两把钥匙，三个数据域

  • AES-GCM：对称加密，密钥由你在设置页配置，只保存在本机浏览器里，永远不会上传。
  • keyHash 校验：每条密文都带加密密钥的指纹。拉取端如果发现自己的密钥对不上，说明这条数据属于别人的个人域——直接跳过，不解密、不落库。
  • 安全兜底：归属为 personal 的数据禁止用团队密钥加密；没配个人私钥时，个人数据只留在本机，不上传。
  • 分片：大内容切成 __sync_chunk__ 分片操作，接收端收齐后重组再解密。
  • 时钟偏移检测：引擎会留意本地时间与服务器时间的偏差，偏差过大时提醒你——因为 LWW 冲突解决依赖准确的时间戳。

4.3 冲突解决与一致性：为什么不需要服务器时间

  • LWW（Last Write Wins）：同一台设备上后发生的修改覆盖先发生的；跨设备时按操作自带的本地客户端时间戳判定先后。每台设备的时钟只影响自己，不会被别人的慢时钟「回滚」。
  • 应用规则：拉来的操作若时间戳新于本地同主键记录，则覆盖；否则忽略。对测试运行（testRuns）等特殊表还有专门的合并逻辑，保留更完整的执行信息。
  • 幂等与防循环：同步写入统一打上 tx.source === 'sync' 标记，钩子据此跳过登记，杜绝「拉下来的数据又被推回去」的反馈循环。
  • 断网与崩溃：变更先落本地队列，同步可随时中断恢复；打开侧边栏时也会自动触发一次拉取（AutoPull）。后台的 PUSH_RETRY 闹钟负责把失败批次留到网络恢复后补推。
  • 紧急出口：设置页提供「重建本地数据」（清空本地团队同步数据后从服务器重新拉取；个人数据按是否配置个人私钥决定是否一并重建）与「清除同步数据」两个兜底操作，用于修复本地状态错乱。

功能模块详解

每个模块都遵循同一套范式：UI（侧边栏）→ db 助手 → Dexie → （可选）同步钩子。差异在于各自的数据来源与外部系统交互。

AI 助手对话 + 工具执行 + 页面任务

不只是聊天。AI 助手通过「工具注册表」拿到操作整个 DPP 的能力：查询黑板、搜索链接、触发 Jenkins 构建、读取录制列表……并且能在高影响操作前弹出确认。

对话如何运转

  1. 多模型供应商：内置 Google / OpenAI / Anthropic / opencode 等多家供应商的接入层，可切换也可自填接口地址；统一走流式输出。
  2. 系统提示词：启动时拼装当前可用工具清单、页面上下文与角色设定，告诉模型「你能做什么」。
  3. 工具调用循环：模型返回 tool_call → 前端执行真实工具（查库/发请求）→ 把结果喂回模型 → 继续生成，直到给出最终答复。
  4. 会话持久化：对话历史存在本地数据库，可回溯；新会话互相隔离。

内置工具族（20+ 组）

配置与状态（aiConfig / dppConfig / session）· 数据查询与修改（blackboard / links / tags / recentActivities / hotnews）· 工程操作（jenkins / recorder / browserTask）· 测试资产（testCases / testProjects / testRuns）· 实用计算（calculator / dateTime / unitConversion / developerUtilities）· 规划与提示词（plan / prompts）。

安全闸：工具确认

写操作类工具（改数据、触发构建等）默认会先弹出确认卡片，展示将要发生的动作，确认后才执行；出现多个待确认工具时可以一键全部确认。若开启 YOLO 模式（AI 头部按钮），确认会被跳过、工具直接执行。

页面任务（Browser Task）

选择目标标签页后，AI 可驱动真实页面：侧边栏与 Background 建立长连接端口，Background 通过 PageAgent 向页面内容脚本下发指令（点击、填写、读取），页面执行结果沿原路返回给模型，形成「观察 → 决策 → 操作」的循环。任务中断后在后台可恢复。

黑板团队域 · 可同步

碎片信息与中英文排查笔记的沉淀地。写入即同步：内容的增删改全部经 db 助手，钩子自动登记同步操作；其他设备在下一次拉取时（打开侧边栏或自动同步）就能看到更新。

  • 编辑：Markdown 语法，失焦自动保存；支持置顶、锁定（防误改）与删除。
  • 与其他模块：黑板内容可被 AI 助手检索与总结（blackboard 工具族）；未来规划支持把内容标记为「个人」以用个人私钥保护。
Jenkins后台代理请求 · 团队域配置

在侧边栏里完成看 Job、查构建、触发构建、跟踪 Pipeline 全流程，不用在 Jenkins 网页和工具之间来回切换。

为什么请求要走 Background

浏览器的跨域限制会让侧边栏直接请求 Jenkins 时被 CORS 拦下。因此所有 Jenkins API 调用都被打包成消息（JENKINS_* 系列），由 Background 的处理器代发——必要时经代理处理器转发——再把结果带回侧边栏。令牌等敏感信息也不暴露给页面上下文。

一次构建的完整流程

  1. 配置环境：添加 Jenkins 地址 + API Token，支持多套环境（开发/测试/生产）切换。在 Jenkins 配置页生成新 Token 时，内容脚本会注入「保存到 DPP」按钮，一键把 Token 存入扩展（而不是替你填表）。
  2. 浏览：拉取 Job 树/我的构建/构建队列；Job 可打标签归类。
  3. 触发：选择 Job 与参数 → 后台请求 buildWithParameters → 轮询队列项拿到构建号。
  4. 跟踪：构建状态轮询展示；支持查看 Pipeline 各阶段/节点日志、测试结果、制品下载，以及中止构建/取消排队。
  5. 通知联动：构建结果可推送到你配置的通知渠道（见设置页「消息」）。
录制 + 禅道增强 + 播放器跨上下文链路 · 三端协作

这是全应用最复杂的一条链路，横跨「目标网页 → 内容脚本 → Background → 本地库 → 禅道网页 → 播放器」六个环节：

  • 三路采集：rrweb 记录页面视觉与操作；控制台拦截器抓取日志（深层对象会安全克隆、超长串截断）；网络拦截器记录 fetch/XHR 的请求响应，甚至能拼接 SSE 流式正文。三者共用一个事件时间轴。
  • 保存与上限：录制数据经 Background 汇总写入本地库（录制不进入同步）。单次录制的网络/控制台事件设有硬上限（4000 条 / 4MB），超出部分截断并标记，防止超大录像拖垮页面；不再需要时可手动删除。
  • 禅道上传：打开禅道缺陷页时，增强脚本在附件区注入「上传录像」按钮——选择本地录制后直接以 .rrweb.json 附件形式挂到缺陷上，无需下载再上传。
  • 播放：播放器扩展页按 URL 加载 .rrweb.json（如禅道附件），画面回放、控制台日志、网络请求按时间轴联动展示。多人装了 DPP 就能直接在禅道里重现现场。
  • 未保存直放：后台还提供录制事件的临时缓存（5 分钟有效期），不落库的录制也能直接交给播放器页面回放。
链接团队域 · 可同步

团队共享的网址簿。

  • 数据模型：链接与标签多对多关联，标签本身也是可同步实体，因此「哪些链接属于哪个项目/环境」在团队内保持一致。
  • 检索：搜索同时匹配名称、URL、标签与备注；支持置顶高频链接。
  • 互联：AI 助手可代为搜索与新增（links 工具族）；链接可被黑板内容、测试资产引用。
验证器（TOTP）个人域 · 个人私钥加密同步

两步验证码生成器。它是个人数据域的代表：即便多人共用同一台同步服务器，同事也永远无法看到你的验证码。

  1. 本地计算：基于 TOTP 标准（RFC 6238）按密钥+时间窗口本地算出 6/8 位验证码，无需联网， secret 不发给任何服务器。
  2. 导入：扫描当前网页的二维码（内容脚本取图、本地解码），或粘贴 otpauth:// 链接 / Base32 密钥，支持批量。
  3. 安全壳：可设 PIN。离开验证器、收起侧边栏或空闲超时后自动锁定，输 PIN 才能看。PIN 无法找回——遗忘时须验证个人私钥，或（未配私钥时）清空账户重来。
  4. 加密同步：配置个人私钥后，账户数据用个人钥加密进入同步通道；只有你自己的其他设备能解开。
  5. 导出迁移：勾选账户导出为 otpauth:// 文本复制或下载；迁移完成后建议删除明文备份并清理剪贴板。
资讯每日热榜 · 本地缓存

聚合每日热榜与历史归档。

  • 数据来源：按日期拉取远程的 daily_hot_YYYY-MM-DD.md 榜单文件，本地解析成结构化条目（标题、热度、链接、来源）。
  • 缓存策略：拉过的日期存入本地库，重复打开秒开；超过保留窗口的旧日期自动清理，本地不囤积。
  • 交互：按日期浏览与回溯历史，展开来源分组，点击条目打开原文。
工具箱纯本地 · 即用即走

一组临时小工具：文本差异对比、JSON 编辑器、正则表达式测试器、时间戳转换器、树形数据对比、React Playground、Vue Playground。处理都在浏览器本地完成、不存数据，关掉即消失——与需要沉淀的数据模块形成互补。

消息Telegram Bot · 事件触达

设置页的「消息」只负责配置通道：把 DPP 里发生的事推送到通知渠道，目前支持 Telegram。

  1. 配置目标：在设置页填写机器人 Token 与接收对象；支持多个目标（如个人群、项目群）。URL 会被规范化校验，只接受 http(s)。
  2. 模板渲染：消息正文由可编辑模板渲染，变量以 Jenkins 构建为中心：环境、任务、构建编号、结果、耗时、参数、变更、产物、日志等；默认模板用于通道试发。
  3. 投递：经后台调用 Telegram API 发送；支持试发验证配置，失败会给出可读的错误提示。
  4. 触发点：Jenkins 构建完成等关键事件；通道配置本身存在团队域里，团队共用一套规则，各功能模块自己保存通知模板。
其他能力速览藏在细节里
  • 禅道集成：在禅道缺陷页注入「上传录像」按钮把本地录制挂为附件；打开 .rrweb.json 附件时可直接调起播放器回放现场。
  • 测试资产管理：测试用例以加密物料（materials）形式存储，另有测试项目与执行记录（testProjects / projectRuns / testRuns），均为团队域可同步实体；AI 助手可代为整理与生成。
  • 审计历史：审计模块从同步操作日志回放关键表（黑板/链接/标签/素材/测试执行等）的变更轨迹，支持分片重组，谁改了什么有据可查。
  • 黑板页：黑板还有一个全屏独立页面，适合长文编辑与投屏查看。
  • 界面定制：功能开关可以按需在设置页关掉不用的模块（极简模式），标签页支持固定与最近使用排序。
  • 深色模式：跟随系统或手动切换，主题偏好本地保存。

附属机制详解

6.1 Background 消息中枢

侧边栏、内容脚本、设置页之间不直接通信，全部经由 Background 的统一消息路由器。路由表按消息类型前缀分发：

JENKINS_*

约 20 种消息：查 Job/构建/队列、触发/取消构建、Pipeline 阶段与日志、制品下载。统一由 Jenkins 处理器代发请求。

RECORDER_*

录制开始/暂停/保存/事件上报；录制状态机与过期状态清理也在这里。

GLOBAL_SYNC_* / AUTO_SYNC_*

手动同步（开始 / 推送 / 拉取）与自动触发推拉。侧边栏的同步按钮就是发这类消息。

BROWSER_TASK_*

AI 页面任务的启动/停止/恢复/查询；另有一条长连接 Port 维持任务宿主。

ZEN_FETCH_JSON

代理请求出口，用于取回禅道侧需要绕开页面限制的 JSON 数据。

REMOTE_RECORDING_* / OPEN_PLAYER_TAB

录制事件的临时缓存与播放器页面打开。

通用消息

OPEN_SIDE_PANEL / SAVE_JENKINS_TOKEN / CAPTURE_VISIBLE_TAB / JENKINS_VALIDATE_CONTENT_ORIGIN。

此外还有一道消息鉴权关卡（messageAuthorization）：不是谁发来的消息 Background 都接，敏感消息会核对发送者身份，防止恶意网页伪造扩展消息。

定时闹钟（Alarms）：PUSH_RETRY 负责补推失败的同步批次；ANALYTICS_FLUSH 负责定时冲刷统计事件。闹钟由浏览器托管，关掉侧边栏后依然生效。

6.2 地址栏搜索（Omnibox）

在地址栏输入 dpp 再加关键词（支持 #标签 过滤），即可搜索已收藏的链接与 Jenkins Job。回车时：命中 Job 会直接打开 Jenkins 工作台窗口，命中链接则打开对应网址——不用先点开侧边栏。

6.3 数据管理

  • 导出：按分类（链接/黑板/配置等）打包成 JSON 下载，敏感项（个人私钥等）默认不导出。
  • 导入：选择分类合并进本地；Jenkins 环境等冲突配置有专门的 reconcile 逻辑，不会盲目覆盖。
  • 重建：清空本地团队同步数据后从服务器重新拉取，用于修复本地状态；未同步上服务器的本地团队数据会丢失，操作前有明确提示。
  • 危险区：一键清除全部本地数据，操作前有确认。

6.4 统计分析

  • 事件采集：功能使用事件（本地表，local 数据域）先写本地库，再由后台闹钟批量冲刷到配置的上报端点；未配置端点时只留在本地。
  • 服务端看板：同步 Worker 内置一个不可猜测路径的用量看板，管理员凭独立密钥查看聚合统计——只看到匿名计数，看不到任何业务内容。

安全模型总结

端到端加密
  • AES-GCM 加密后才离机，密钥只在本机
  • 服务端与管理员只见密文与计数
  • keyHash 校验，错钥数据自动跳过
  • 大内容分片，逐片校验哈希
双密钥隔离
  • 团队密钥保护共享数据
  • 个人私钥保护验证器等私密数据
  • 个人数据禁止回落团队密钥
  • 未配私钥时个人数据只留本机
本地优先
  • 数据先写本地，离线完整可用
  • 冲突按本地时间戳 LWW 解决
  • 软删除可恢复、可追溯
  • local 域数据（统计）永不出机
操作可控
  • AI 写操作默认需确认（YOLO 模式可自动放行）
  • 后台消息有发送者鉴权
  • 导出默认排除密钥类敏感项
  • 危险操作（清库）二次确认

同步服务器由你自己部署（Cloudflare Worker + D1），只存密文与操作日志；开启自动同步后，数据会按设定间隔自动推拉。更多配置见设置页的「数据同步配置」。本文描述与代码实现保持一致，实现细节以源码为准。
