# 模块互联设计建议

## 1. 背景

当前应用已经包含黑板、Jenkins、链接、录制、资讯、AI、TOTP 和工具箱等多个模块。基础设施也已经具备一定的互联能力：

- 主要模块共享 Dexie 数据库；
- 链接、Job 和标签之间已经存在关联表；
- background 已经承担浏览器消息中枢的角色；
- 录制、禅道、Jenkins 之间已经存在部分业务连接；
- SyncEngine 为可同步数据提供了统一基础。

目前的主要问题不是模块数量不足，而是模块之间缺少共同的工作上下文、统一的实体引用和跨模块事件。因此用户感受到的是一组工具，而不是一个连续的工作系统。

## 2. 目标

将应用从“工具集合”逐步演进为“工作上下文平台”：

> 黑板负责沉淀，录制负责采集，Jenkins 负责验证，禅道负责协作，链接负责导航，AI 负责理解和执行，工作台负责组织上下文。

目标包括：

1. 用户可以从任意模块进入相关模块，而不需要重新查找对象；
2. 页面、项目、环境、禅道任务、构建和录制可以互相引用；
3. 关键业务动作可以触发后续动作，但模块之间不形成直接网状依赖；
4. AI 可以在权限和确认机制约束下查询、总结和执行跨模块操作；
5. 同步、权限和敏感数据边界保持清晰。

## 3. 总体设计

建议建立三层连接：

```text
统一工作上下文 WorkContext
          |
统一实体引用 EntityRef / EntityRelations
          |
统一事件与动作 Domain Events / Commands
```

### 3.1 统一工作上下文

应用需要知道用户当前正在处理什么，而不只是当前打开了哪个侧边栏 Tab。

建议逐步引入以下上下文信息：

```ts
interface WorkContext {
  projectId?: string;
  projectName?: string;
  environment?: string;
  currentUrl?: string;
  currentDomain?: string;
  zentaoTaskId?: string;
  jenkinsJobUrl?: string;
  recordingId?: string;
  selectedTags?: string[];
}
```

上下文来源可以包括：

- 当前页面 URL 和域名；
- 当前禅道项目或任务；
- 当前 Jenkins 环境；
- 当前录制会话；
- 当前选中的链接、构建或黑板便签；
- 用户手动选择的项目和环境。

上下文建立后，各模块可以围绕它协作：

- 录制自动关联当前禅道任务；
- Jenkins 构建自动关联项目和环境；
- 新建黑板便签时自动记录当前页面和项目；
- AI 默认只处理当前上下文相关数据；
- 链接列表可以按项目、环境和当前域名过滤。

### 3.2 统一实体引用

模块之间应该保存轻量引用，而不是互相嵌套完整对象，也不应该让一个 feature 直接依赖另一个 feature 的内部类型。

可以采用类似以下的引用模型：

```ts
interface EntityRef {
  type: 'link' | 'job' | 'build' | 'recording' | 'blackboard' | 'zentaoTask';
  id: string;
  title?: string;
  url?: string;
}
```

黑板、录制、AI 会话和构建记录可以保存关联对象：

```ts
interface RelatedEntity {
  type: string;
  id: string;
}
```

示例：

```text
黑板便签
├── 当前页面：https://test.example.com/order/123
├── 关联禅道任务：TASK-1024
├── 关联录制：recording-abc
└── 关联 Jenkins 构建：build-456
```

建议提供通用 UI 组件：

- `RelatedEntities`：展示关联对象；
- `EntityLink`：跨模块跳转；
- `EntityPicker`：选择关联对象；
- `ActivityTimeline`：展示相关活动；
- `ContextBadge`：展示当前项目和环境。

### 3.3 统一事件总线

background 已经承担消息中枢角色，可以进一步发展为类型安全的领域事件入口。

示例事件：

```ts
type DomainEvent =
  | { type: 'recording.created'; recordingId: string }
  | { type: 'recording.completed'; recordingId: string }
  | { type: 'build.started'; buildId: string }
  | { type: 'build.completed'; buildId: string; status: string }
  | { type: 'blackboard.created'; itemId: string }
  | { type: 'link.opened'; linkId: string }
  | { type: 'zentao.task.detected'; taskId: string };
```

模块只发布事件，不直接调用其他模块：

```text
录制完成
  -> 发布 recording.completed
  -> 黑板模块提供排查摘要入口
  -> 禅道模块显示“上传录像”
  -> AI 模块可以分析录制
  -> 活动流记录一次操作
```

这样新增模块时，不需要修改所有已有模块。

## 4. 优先打通的业务链路

### 4.1 录制、禅道、黑板和 AI

这是目前最自然、价值最高的一条链路：

```text
发现问题
  -> 录制页面操作、网络和控制台
  -> 自动关联当前禅道任务
  -> 录制完成后生成黑板排查记录
  -> AI 总结复现步骤、异常请求和控制台错误
  -> 一键生成禅道 Bug 描述
  -> 上传录像和相关日志
```

这可以让录制模块从“录像工具”变成完整的问题排查工作流。

### 4.2 Jenkins、链接和黑板

```text
选择 Jenkins Job
  -> 自动显示对应环境链接
  -> 点击构建后记录构建结果
  -> 构建失败时生成黑板排查项
  -> 黑板中直接跳转 Jenkins 日志和对应环境
```

后续可以继续支持：

- 构建失败自动关联最近一次录制；
- 按项目和环境展示构建历史；
- 黑板便签中直接引用某次构建。

### 4.3 链接、标签和当前页面

链接模块不应只是收藏夹，也可以成为项目和环境导航层：

```text
当前页面属于 test 环境
  -> 推荐该项目的测试链接
  -> 推荐相关 Jenkins Job
  -> 推荐相关禅道任务
  -> 推荐最近的录制和黑板记录
```

当前已有标签体系，可以将标签从单纯的分类字段升级为跨模块的统一关联维度。

### 4.4 AI 与其他模块

AI 可以成为统一查询和操作入口：

- “找出最近 3 次这个项目的 Jenkins 构建失败记录”；
- “把当前录制总结成禅道 Bug 描述”；
- “查找和当前 URL 相关的黑板记录”；
- “把这条热新闻保存为链接并打上标签”；
- “根据当前页面创建一条排查便签”。

AI 应通过统一的服务或命令接口调用能力，而不是直接操作任意 Dexie 表。

以下操作必须保留确认机制：

- 上传禅道；
- 触发 Jenkins 构建；
- 删除数据；
- 修改同步设置；
- 访问敏感 TOTP 数据。

## 5. 工作台入口

当前侧边栏以模块切换为主：

```text
黑板 / Jenkins / 链接 / 录制 / 资讯 / AI / 工具
```

建议增加一个默认的“工作台”入口，但保留现有模块导航。

工作台可以聚合：

- 当前项目、环境和页面上下文；
- 待处理黑板事项；
- 最近失败的构建；
- 当前页面相关链接；
- 最近录制；
- 相关禅道任务；
- 最近活动。

用户进入应用后首先看到的是当前工作状态和下一步动作，而不是必须打开多个 Tab 自己拼接信息。

## 6. 全局搜索与命令入口

建议增加统一搜索入口，搜索范围包括：

- 链接；
- 黑板便签；
- 录制；
- 构建；
- 禅道任务；
- 标签；
- AI 会话。

搜索结果应支持：

- 按类型、项目、环境和时间筛选；
- 直接跳转到对象所在模块；
- 执行安全的关联动作；
- 通过快捷键快速打开。

例如搜索“订单 123”时，可以同时返回相关链接、黑板便签、录制、Jenkins 构建、禅道任务和 AI 会话。

## 7. 数据层演进建议

不要一次性建设完整平台，建议按以下顺序逐步引入通用数据模型：

1. `entityRelations`：记录实体之间的关系；
2. `activityEvents`：记录创建、完成、打开、失败等关键动作；
3. `workContexts`：保存当前项目、环境和页面上下文；
4. `projects`：统一项目和环境定义；
5. `workspaces`：支持更高层的工作区隔离。

职责划分如下：

| 模型 | 作用 |
| --- | --- |
| `entityRelations` | 谁和谁有关 |
| `activityEvents` | 发生过什么 |
| `workContexts` | 当前正在处理什么 |
| `projects` | 项目和环境是什么 |
| `workspaces` | 数据属于哪个工作区 |

新增 Dexie 表时必须增加新的版本迁移，不要修改已发布版本的 schema 定义。还需要明确每张表是否参与 SyncEngine，同步前继续遵守敏感数据加密边界。

## 8. 模块边界原则

为了避免互联后产生新的耦合，实施时应遵守以下原则：

- 不让 Jenkins 直接 import 录制服务；
- 不让黑板保存完整的录制对象；
- 不让每个模块各自定义项目、环境和标签；
- 不用一个全局状态对象承载所有业务逻辑；
- 不让 AI 绕过服务层直接修改任意数据库表；
- 不让 TOTP 等敏感数据进入普通搜索和 AI 上下文；
- 不把模块间跳转误认为真正的模块互联。

模块之间共享的是稳定的实体引用、上下文和事件，而不是彼此的内部实现。

## 9. 分阶段实施路线

### 第一阶段：建立连接基础

- 定义 `EntityRef` 类型；
- 设计 `entityRelations` 表；
- 增加统一的跨模块跳转协议；
- 抽取项目、环境和 URL 的公共识别逻辑；
- 为新增关联数据补充 Dexie migration 和同步范围定义。

### 第二阶段：打通最高价值链路

- 完成“录制 -> 黑板”的关联；
- 完成“录制 -> 禅道任务”的关联；
- 为录制增加 AI 摘要入口；
- 完成“Jenkins 构建 -> 黑板排查项”的关联；
- 增加关联对象展示组件。

### 第三阶段：建立统一工作台

- 引入 `WorkContext`；
- 增加工作台首页；
- 增加统一搜索；
- 增加最近活动和待处理事项；
- 将当前上下文注入 AI 会话。

### 第四阶段：事件驱动和自动化

- 建立类型安全的领域事件；
- 将关键模块动作接入事件总线；
- 增加可确认的跨模块命令；
- 支持构建失败、录制完成等事件的自动化后续动作；
- 完善权限、审计和同步冲突处理。

## 10. 推荐的第一批任务

建议先不要从“大而全的工作台”开始，而是完成以下最小闭环：

1. 为 `recordings` 和 `blackboard` 增加关联引用；
2. 录制完成后允许一键创建黑板排查记录；
3. 黑板记录显示并打开关联录制；
4. 录制和黑板共享当前页面 URL、项目和环境信息；
5. 增加一个简单的“相关内容”区域；
6. 在此基础上再接入禅道和 AI。

这个闭环可以验证实体引用、跨模块导航、上下文保存和同步策略，风险和改动范围都相对可控。
