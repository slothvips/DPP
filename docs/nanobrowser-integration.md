# Nanobrowser Browser Engine Integration

The browser engine source is mirrored in `vendor/nanobrowser` from the Apache-2.0
licensed Nanobrowser repository:

```text
https://github.com/nanobrowser/nanobrowser.git
```

The current mirror commit is recorded in `vendor/nanobrowser-upstream.json`.
Do not edit files under `vendor/nanobrowser` or
`src/lib/browserEngine/upstream` by hand — both are regenerated by the sync
script. DPP integrations belong in `src/lib/browserEngine` (outside `upstream/`)
and should depend on the adapter boundary rather than Nanobrowser's agent,
prompt, provider, or UI code.

The script also regenerates the bundler-friendly engine slice under
`src/lib/browserEngine/upstream` (browser/, dom/, log.ts, LICENSE) and copies
`public/buildDomTree.js` (the page-side DOM builder injected via
`chrome.scripting`). `browser/context.ts` is intentionally excluded because DPP
ships its own `NanobrowserContext` adapter in
`src/lib/browserEngine/nanobrowserContext.ts`.

Runtime requirements: the engine attaches to tabs via CDP
(`chrome.debugger`, permission added), builds DOM state through
`chrome.scripting` + `chrome.webNavigation`, so the task host only supports
Chrome/Chromium for now.

To update the mirror from a local Nanobrowser checkout:

```bash
pnpm sync:nanobrowser /path/to/nanobrowser main
```

After an update, run `pnpm compile`, `pnpm lint`, `pnpm test`, and `pnpm build`.
The browser adapter contract and Chrome multi-tab regression tests must pass
before accepting a new upstream commit.
